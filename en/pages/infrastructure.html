🧩 Role distribution — virtual machines
VMRoleBaseKey components

VM215Shared services — no GPUUbuntu Server 24.04 LTS · dedicated ext4 diskPostgreSQL 18.4 · pgvector 0.8.6 (RAG vector backend)
VM300AI consumer — automationUbuntu Server 24.04 LTS · no GPUn8n (workflow orchestration) · auto-start
Principle: the GPU is assigned directly to the VMs that need it; GPU workloads (VM210) and shared CPU services (VM215) are kept separate to limit dependencies and ease backups.

Industrialization: the VMs are derived from generic and CUDA templates, customized via Cloud-Init; rebuilding them follows a reversible procedure (a control clone is validated before any replacement).

Limitations: a diagnostic 400 W software cap was used previously (versus 600 W by default); the latest ComfyUI/Ollama tests were run at 600 W, with no guarantee of long-term stability nor an established performance comparison (procedure on the AI & LLM page). ZFS snapshots also ease technical rollbacks but do not replace an independent backup — that policy is still being defined.
