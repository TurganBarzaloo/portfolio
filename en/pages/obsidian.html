Obsidian

Personal knowledge base — living documentation of the On-Premise AI infrastructure

Markdown Note-taking Knowledge base Link graph Local-first
Documentation · Intermediate · 2024-2026
Why Obsidian? When building an AI infrastructure from scratch — Proxmox, GPU passthrough, local LLMs, RAG, Python pipelines — memory is no longer enough. I needed a tool that stores my notes locally, in pure Markdown, with no cloud subscription, and that links concepts together. Obsidian has been the building companion for this entire infrastructure: every command tested, every error encountered, every architecture decision has been logged in a dedicated vault. This portfolio is, in part, the public synthesis of it.
Overview

Obsidian is a local-first Markdown note editor: files stay on disk, in plain text format. No account required, no data sent to the cloud by default. Its strength lies in the bidirectional link graph ([[wikilink]]) that turns isolated notes into a navigable knowledge network.

  • Markdown files stored locally (C:\Notes\infra-vault)
  • Interactive graph of links between concepts
  • Instant full-text search across the whole vault
  • Templates to standardize note-taking
  • Community plugins (Dataview, Kanban, Calendar…)
  • Optional sync via OneDrive or Git

Concrete role in building the infrastructure

The infra-vault vault has accompanied every stage of the project, from the technology watch phase to the writing of this portfolio. Here are the uses that really made a difference:

📋 Build journal

One note per work session: goal, commands tested, errors encountered, solution adopted. Essential for resuming a task after several days off without losing context.

markdown — illustrative example of a session note (does not describe the current platform)
## 2024-11-14 — GPU Passthrough VFIO
**Objectif :** Isoler la RTX 3090 pour la VM LLM

### Commandes testées
```bash
lspci -nn | grep NVIDIA
# 0000:01:00.0 [10de:2204]
```
### Problème rencontré
IOMMU group partagé → ajouter pcie_acs_override=downstream

### Solution
Kernel param : `intel_iommu=on iommu=pt pcie_acs_override=downstream,multifunction`

→ [[gpu_passthrough]] pour la doc finale

🗺️ Architecture mind map

Every infrastructure component has its own dedicated note, linked via wikilinks. The Obsidian graph visualizes dependencies in real time: Proxmox → LLM VM → Docker → Ollama → Open WebUI.

📚 Technology watch base

Articles, model benchmarks, comparisons (LLaMA vs Mistral vs Phi), reading notes on RAG and Qdrant. All centralized, retrievable in 3 seconds via full-text search.

Vault graph view

Obsidian's graph view visually connects notes: each dot is a note, each line a link. It reveals thematic clusters (infrastructure, AI, DevOps…) and the vault's central notes.

Intermediate
Example — Dataview query

Dataview lets you query the vault like a database. Example: display all in-progress infra tasks, sorted by last modification date.

dataview — open-tasks dashboard
```dataview
TABLE
  file.mtime AS "Dernière modif",
  status AS "Statut",
  tags AS "Tags"
FROM "02-infrastructure" OR "03-ia"
WHERE status = "en-cours"
SORT file.mtime DESC
```
Result: a table automatically updated every time the vault is opened — no manual entry. Same principle as a project view in a tool like Notion, but entirely local and in plain Markdown.
From the Obsidian vault to this portfolio

This portfolio was not written from scratch. Each HTML page is the publishable version of an existing Obsidian note, enriched and formatted. The workflow is simple:

📝
1. Session note
Raw note-taking during the build
↓
🗂️
2. Technical sheet
Consolidation into 02-infrastructure/ or 03-ia/
↓
📄
3. Portfolio draft
Writing in 06-portfolio/
↓
🌐
4. Published HTML page
portfolio.stephanemuraro.fr

Key advantage: the Obsidian note remains the source of truth. If a config changes (Proxmox version, updated LLM model), the note is updated first, then the HTML page is synced.

This flow also keeps unpublished information in the vault (API keys, internal IP addresses, sensitive debug notes) with no risk of exposing it on GitHub.

The vault itself is versioned on a private GitHub repository, separate from the portfolio's public repository.
