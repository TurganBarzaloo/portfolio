Obsidian

Base de conocimiento personal — documentación viva de la infraestructura de IA On-Premise

Markdown Toma de notas Knowledge base Grafo de enlaces Local-first
Documentación · Intermedio · 2024-2026
¿Por qué Obsidian? Al construir una infraestructura de IA desde cero — Proxmox, GPU passthrough, LLM locales, RAG, pipelines de Python —, la memoria ya no basta. Necesitaba una herramienta que guardara mis notas localmente, en Markdown puro, sin suscripción en la nube, y que conectara los conceptos entre sí. Obsidian ha sido el compañero de construcción de toda esta infraestructura: cada comando probado, cada error encontrado, cada decisión de arquitectura se ha registrado en un vault dedicado. Este portfolio es, en parte, la síntesis pública de ello.
Presentación

Obsidian es un editor de notas Markdown local-first: los archivos permanecen en el disco, en formato de texto plano. No requiere cuenta, y por defecto no se envía ningún dato a la nube. Su fuerza reside en el grafo de enlaces bidireccionales ([[wikilink]]) que convierte notas aisladas en una red de conocimiento navegable.

  • Archivos Markdown almacenados localmente (C:\Notes\infra-vault)
  • Grafo interactivo de enlaces entre conceptos
  • Búsqueda de texto completo instantánea en todo el vault
  • Plantillas para estandarizar la toma de notas
  • Plugins de la comunidad (Dataview, Kanban, Calendar…)
  • Sincronización opcional vía OneDrive o Git

Papel concreto en la construcción de la infraestructura

El vault infra-vault ha acompañado cada etapa del proyecto, desde la fase de vigilancia tecnológica hasta la redacción de este portfolio. Estos son los usos que realmente marcaron la diferencia:

📋 Diario de construcción

Una nota por sesión de trabajo: objetivo, comandos probados, errores encontrados, solución adoptada. Indispensable para retomar una tarea tras varios días de interrupción sin perder el contexto.

markdown — ejemplo ilustrativo de nota de sesión (no describe la plataforma actual)
## 2024-11-14 — GPU Passthrough VFIO
**Objectif :** Isoler la RTX 3090 pour la VM LLM

### Commandes testées
```bash
lspci -nn | grep NVIDIA
# 0000:01:00.0 [10de:2204]
```
### Problème rencontré
IOMMU group partagé → ajouter pcie_acs_override=downstream

### Solution
Kernel param : `intel_iommu=on iommu=pt pcie_acs_override=downstream,multifunction`

→ [[gpu_passthrough]] pour la doc finale

🗺️ Mapa mental de la arquitectura

Cada componente de la infraestructura tiene su propia nota dedicada, enlazada mediante wikilinks. El grafo de Obsidian visualiza en tiempo real las dependencias: Proxmox → VM LLM → Docker → Ollama → Open WebUI.

📚 Base de vigilancia tecnológica

Artículos, benchmarks de modelos, comparativas (LLaMA vs Mistral vs Phi), notas de lectura sobre RAG y Qdrant. Todo centralizado, localizable en 3 segundos mediante la búsqueda de texto completo.

Vista de grafo del vault

La vista de grafo de Obsidian conecta visualmente las notas: cada punto es una nota, cada línea un enlace. Revela los grupos temáticos (infraestructura, IA, DevOps…) y las notas centrales del vault.

Intermedio
Ejemplo — Consulta Dataview

Dataview permite consultar el vault como una base de datos. Ejemplo: mostrar todas las tareas de infraestructura en curso, ordenadas por fecha de última modificación.

dataview — panel de tareas abiertas
```dataview
TABLE
  file.mtime AS "Dernière modif",
  status AS "Statut",
  tags AS "Tags"
FROM "02-infrastructure" OR "03-ia"
WHERE status = "en-cours"
SORT file.mtime DESC
```
Resultado: una tabla actualizada automáticamente cada vez que se abre el vault — sin introducción manual. Es el mismo principio que una vista de proyecto en una herramienta como Notion, pero totalmente local y en Markdown puro.
Del vault de Obsidian a este portfolio

Este portfolio no se redactó desde cero. Cada página HTML es la versión publicable de una nota de Obsidian existente, enriquecida y formateada. El flujo de trabajo es simple:

📝
1. Nota de sesión
Toma de notas en bruto durante la construcción
↓
🗂️
2. Ficha técnica
Consolidación en 02-infrastructure/ o 03-ia/
↓
📄
3. Borrador del portfolio
Redacción en 06-portfolio/
↓
🌐
4. Página HTML publicada
portfolio.stephanemuraro.fr

Ventaja clave: la nota de Obsidian sigue siendo la fuente de verdad. Si cambia una configuración (versión de Proxmox, modelo LLM actualizado), primero se actualiza la nota y después se sincroniza la página HTML.

Este flujo también permite mantener información no publicada en el vault (claves de API, direcciones IP internas, notas de depuración sensibles) sin riesgo de exponerla en GitHub.

El propio vault está versionado en un repositorio de GitHub privado, distinto del repositorio público del portfolio.
