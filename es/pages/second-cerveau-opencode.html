Segundo Cerebro OpenCode

Kit Markdown · OpenCode · memoria duradera · validación humana · licencia MIT

Nivel: Intermedio
Segundo Cerebro OpenCode es un kit mínimo en Markdown para estructurar el trabajo en torno a proyectos, documentos fuente y síntesis. OpenCode actúa como agente único; son los archivos Markdown los que sostienen la memoria duradera, de modo que retomar el trabajo no dependa de una conversación anterior. Estado: prototipo utilizable, publicado en GitHub desde el 4 de octubre de 2026, cuya recepción funcional completa queda por repetir con OpenCode 2.0.22.

Ver el repositorio de GitHub →

🎯 Utilidad para el lector
  • Una ficha de proyecto es la referencia para tareas, decisiones, diario y punto de reanudación
  • Las fuentes originales se mantienen separadas de las síntesis y se tratan como datos, no como instrucciones
  • Dos rituales de OpenCode: /ouvrir (apertura en solo lectura) y /clore (cierre que somete primero los cambios a validación humana)
  • Un vault de ejemplo ficticio permite recorrer el funcionamiento sin datos personales ni profesionales reales

El proyecto no incluye ni base de datos vectorial, ni MCP, ni plugin, ni automatización permanente: estas extensiones se difieren hasta que se observe una necesidad real.

🧭 Soberanía y gobernanza

El kit está diseñado para funcionar con OpenCode y un modelo accesible mediante una API compatible con OpenAI en la red local o en la propia máquina. Esta disposición puede reducir la dependencia de un proveedor de inferencia externo en los usos considerados, manteniendo el vault real separado del kit publicable.

El enfoque está inspirado en ISO/IEC 27001:2022: separación de fuentes y síntesis, control humano antes de escribir, exclusión de los secretos de la configuración versionada, conservación de la trazabilidad.

No se reivindica ninguna conformidad ni certificación ISO 27001. La autenticación, el transporte y el registro del servicio de inferencia dependen de ese servicio, no del kit.
🔐 Seguridad y límites
  • Los ejemplos versionados son ficticios; los datos reales deben permanecer en un vault privado separado
  • La configuración local y el registro de riesgos están excluidos de Git
  • El uso compartido de conversaciones está desactivado en la configuración prevista
  • Las llamadas web, shell, plugins, MCP y subagentes están excluidos del perímetro previsto del prototipo
Límites explícitos: los permisos de OpenCode no constituyen un aislamiento técnico, la sobriedad de lectura depende en parte del modelo, y pueden existir vías de ejecución fuera de los permisos documentados. Estas medidas no sustituyen los controles del equipo, de la red o del servicio de IA.
