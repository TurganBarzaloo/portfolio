VM302 — Estación de desarrollo IA

Windows 11 · VSCodium · Python 3.13 · Node.js 24 LTS · DeepSeek Harness · inferencia GPU remota

Nivel: Avanzado
VM302 es una estación de desarrollo Windows 11 dedicada al desarrollo políglota y a la evaluación de asistentes de programación. La máquina no tiene GPU local: consume una capacidad de inferencia alojada por separado, lo que separa la estación cliente del servicio de cómputo.
✅ Base y cadenas validadas
  • Base Windows 11 virtualizada, sin acelerador GPU local
  • VSCodium, Git y PowerShell 7 validados mediante pruebas funcionales
  • Identidad de invitado, red, agente de invitado y periféricos revalidados
  • Python 3.13 — gestión de paquetes, entorno virtual, prueba sin conexión de bibliotecas estándar
  • Node.js 24 LTS y npm — ejecución de una prueba local de JavaScript
  • DeepSeek Harness en una versión preliminar fijada: lockfile, integridad del paquete, auditoría de dependencias, scripts de instalación y módulos nativos verificados
  • Interfaz de Harness limitada a la máquina local, primer perfil en solo lectura
🔎 Inferencia remota y persistencia
  • Primera inferencia remota validada con qwen3.6:35b: la instrucción de control devolvió exactamente DSH_VM302_QWEN36_OK, sin llamada a herramientas
  • Tras un reinicio de la estación: versiones, configuración e historial de sesión persistidos
  • Nueva sesión que confirma la respuesta esperada y la aceleración GPU remota
  • Acceso al servicio de inferencia limitado a la red privada, sin publicación directa de su API en Internet
  • Servicios de automatización comprobados a nivel de estado, sin declarar aún consumo por un agente
🧭 Arquitectura — estación cliente, cómputo separado
separación entre la estación de desarrollo y el servicio de inferencia
VM302 (Windows 11, sin GPU local)
├── VSCodium · Git · PowerShell 7
├── Python 3.13 · Node.js 24 LTS
└── DeepSeek Harness (interfaz local)
    └── servicio de inferencia separado (red privada)
        └── aceleración GPU remota

La estación permanece ligera y sin GPU: el cómputo se delega a un servicio de inferencia alojado por separado, accesible solo en la red privada. Esta separación aísla las herramientas de desarrollo del servicio del modelo.

🎯 Competencias demostradas
  • Preparación y validación de una estación Windows virtualizada
  • Diseño de una cadena de desarrollo políglota
  • Instalación controlada de una herramienta agéntica basada en una arquitectura de plugins Cordis
  • Integración de una estación sin GPU con un servicio de inferencia separado
  • Selección de componentes libres y separación de dependencias propietarias
  • Pruebas reproducibles y validación sin conexión
  • Separación entre estación cliente, servicio de inferencia y automatización
🚧 Límites y estado:
  • las cadenas Rust y C/C++ siguen siendo trabajo futuro;
  • la comparación de asistentes y la ejecución de un flujo de automatización por un agente están aún por realizar;
  • DeepSeek Harness se distribuye todavía como versión preliminar: no se presenta como un componente estabilizado;
  • la licencia de Windows y los componentes de hardware propietarios impiden presentar el conjunto como «100 % código abierto».
