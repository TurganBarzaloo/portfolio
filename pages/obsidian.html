Obsidian

Base de connaissance personnelle — documentation vivante de l'infrastructure IA On-Premise

Markdown Prise de notes Knowledge base Graph de liens Local-first
Documentation · Intermédiaire · 2024-2026
Pourquoi Obsidian ? Quand on construit une infrastructure IA from scratch — Proxmox, GPU passthrough, LLM locaux, RAG, pipelines Python — la mémoire ne suffit plus. J'avais besoin d'un outil qui stocke mes notes localement, en Markdown pur, sans abonnement cloud, et qui relie les concepts entre eux. Obsidian a été le compagnon de construction de toute cette infrastructure : chaque commande testée, chaque erreur rencontrée, chaque décision d'architecture ont été consignées dans un vault dédié. Ce portfolio en est en partie la synthèse publique.
Présentation

Obsidian est un éditeur de notes Markdown local-first : les fichiers restent sur le disque, au format texte brut. Aucun compte requis, aucune donnée envoyée dans le cloud par défaut. Sa force réside dans le graphe de liens bidirectionnels ([[wikilink]]) qui transforme des notes isolées en réseau de connaissance navigable.

  • Fichiers Markdown stockés localement (C:\Notes\infra-vault)
  • Graphe interactif des liens entre concepts
  • Recherche full-text instantanée sur tout le vault
  • Templates pour standardiser la prise de notes
  • Plugins communautaires (Dataview, Kanban, Calendar…)
  • Synchronisation optionnelle via OneDrive ou Git

Rôle concret dans la construction de l'infrastructure

Le vault infra-vault a accompagné chaque étape du projet, de la phase de veille technologique jusqu'à la rédaction de ce portfolio. Voici les usages qui ont réellement fait la différence :

📋 Journal de construction

Une note par session de travail : objectif, commandes testées, erreurs rencontrées, solution retenue. Indispensable pour reprendre un chantier après plusieurs jours d'interruption sans perdre le contexte.

markdown — exemple de note de session
## 2024-11-14 — GPU Passthrough VFIO
**Objectif :** Isoler la RTX 3090 pour la VM LLM

### Commandes testées
```bash
lspci -nn | grep NVIDIA
# 0000:01:00.0 [10de:2204]
```
### Problème rencontré
IOMMU group partagé → ajouter pcie_acs_override=downstream

### Solution
Kernel param : `intel_iommu=on iommu=pt pcie_acs_override=downstream,multifunction`

→ [[gpu_passthrough]] pour la doc finale

🗺️ Carte mentale de l'architecture

Chaque composant de l'infra possède sa note dédiée, reliée par des wikilinks. Le graphe Obsidian visualise en temps réel les dépendances : Proxmox → VM LLM → Docker → Ollama → Open WebUI.

📚 Base de veille technologique

Articles, benchmarks de modèles, comparatifs (LLaMA vs Mistral vs Phi), notes de lecture sur le RAG et Qdrant. Tout centralisé, retrouvable en 3 secondes via la recherche full-text.

Intermédiaire
Exemple — Requête Dataview

Dataview permet d'interroger le vault comme une base de données. Exemple : afficher tous les chantiers infra en cours, triés par date de dernière modification.

dataview — tableau de bord chantiers ouverts
```dataview
TABLE
  file.mtime AS "Dernière modif",
  status AS "Statut",
  tags AS "Tags"
FROM "02-infrastructure" OR "03-ia"
WHERE status = "en-cours"
SORT file.mtime DESC
```
Résultat : un tableau mis à jour automatiquement à chaque ouverture du vault — aucune saisie manuelle. C'est le même principe qu'une vue de projet dans un outil comme Notion, mais entièrement local et en Markdown brut.
Du vault Obsidian à ce portfolio

Ce portfolio n'a pas été rédigé depuis zéro. Chaque page HTML est la version publiable d'une note Obsidian existante, enrichie et mise en forme. Le flux de travail est simple :

📝
1. Note de session
Prise de notes brute pendant la construction
↓
🗂️
2. Fiche technique
Consolidation dans 02-infrastructure/ ou 03-ia/
↓
📄
3. Brouillon portfolio
Rédaction dans 06-portfolio/
↓
🌐
4. Page HTML publiée
portfolio.stephanemuraro.fr

Avantage clé : la note Obsidian reste la source de vérité. Si une config change (version de Proxmox, modèle LLM mis à jour), on met à jour la note, puis on synchronise la page HTML.

Ce flux permet aussi de garder des informations non publiées dans le vault (clés d'API, adresses IP internes, notes de debug sensibles) sans risque de les exposer sur GitHub.

Le vault est lui-même versionné sur un dépôt GitHub privé, distinct du dépôt public du portfolio.
