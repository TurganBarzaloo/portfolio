Second Cerveau OpenCode

Kit Markdown · OpenCode · mémoire durable · validation humaine · licence MIT

Niveau : Intermédiaire
Second Cerveau OpenCode est un kit minimal en Markdown pour structurer le travail autour de projets, de documents sources et de synthèses. OpenCode y sert d'agent unique ; ce sont les fichiers Markdown qui portent la mémoire durable, afin que la reprise ne dépende pas d'une conversation antérieure. Statut : prototype utilisable, publié sur GitHub depuis le 4 octobre 2026, dont la recette fonctionnelle complète reste à refaire sur OpenCode 2.0.22.

Voir le dépôt GitHub →

🎯 Utilité pour le lecteur
  • Une fiche projet fait autorité pour les tâches, décisions, journal et point de reprise
  • Les sources originales restent distinctes des synthèses et sont traitées comme des données, non comme des consignes
  • Deux rituels OpenCode : /ouvrir (ouverture en lecture seule) et /clore (clôture qui soumet d'abord les changements à validation humaine)
  • Un vault d'exemple fictif permet de parcourir le fonctionnement sans donnée personnelle ni professionnelle réelle

Le projet ne fournit ni base vectorielle, ni MCP, ni plugin, ni automatisation permanente : ces extensions restent différées jusqu'à l'expression d'un besoin observé.

🧭 Souveraineté et gouvernance

Le kit est conçu pour fonctionner avec OpenCode et un modèle joignable par une API compatible OpenAI sur le réseau local ou sur la machine. Cette disposition peut réduire la dépendance à un fournisseur d'inférence externe pour les usages concernés, tout en gardant le vault réel séparé du kit publiable.

La démarche est inspirée d'ISO/IEC 27001:2022 : séparation des sources et des synthèses, contrôle humain avant écriture, exclusion des secrets de la configuration versionnée, conservation de la traçabilité.

Aucune conformité ni certification ISO 27001 n'est revendiquée. L'authentification, le transport et la journalisation du service d'inférence relèvent de ce service, pas du kit.
🔐 Sécurité et limites
  • Les exemples suivis sont fictifs ; les données réelles doivent rester dans un vault privé séparé
  • La configuration locale et le registre de risques sont exclus de Git
  • Le partage de conversations est désactivé dans la configuration prévue
  • Appels web, shell, plugins, MCP et sous-agents sont exclus du périmètre prévu du prototype
Limites explicites : les permissions d'OpenCode ne forment pas une isolation technique, la sobriété de lecture dépend en partie du modèle, et des voies d'exécution peuvent exister hors des permissions documentées. Ces mesures ne remplacent pas les contrôles du poste, du réseau ou du service IA.
