VM302 — Station de développement IA

Windows 11 · VSCodium · Python 3.13 · Node.js 24 LTS · DeepSeek Harness · inférence GPU distante

Niveau : Avancé
VM302 est un poste de développement Windows 11 dédié au développement polyglotte et à l'évaluation d'assistants de programmation. La station ne possède pas de GPU local : elle consomme une capacité d'inférence hébergée séparément, ce qui sépare le poste client du service de calcul.
✅ Socle & chaînes validées
  • Socle Windows 11 virtualisé, sans accélérateur GPU local
  • VSCodium, Git et PowerShell 7 validés par essais fonctionnels
  • Identité invitée, réseau, agent invité et périphériques revalidés
  • Python 3.13 — gestion des paquets, environnement virtuel, test hors ligne de bibliothèques standards
  • Node.js 24 LTS et npm — exécution d'un test JavaScript local
  • DeepSeek Harness en version préliminaire épinglée : lockfile, intégrité du paquet, audit des dépendances, scripts d'installation et modules natifs contrôlés
  • Interface du Harness limitée à la machine locale, premier profil en lecture seule
🔎 Inférence distante & persistance
  • Première inférence distante validée avec qwen3.6:35b : la consigne de contrôle a retourné exactement DSH_VM302_QWEN36_OK, sans appel d'outil
  • Après redémarrage de la station : versions, configuration et historique de session persistés
  • Nouvelle session confirmant la réponse attendue et l'accélération GPU distante
  • Accès au service d'inférence limité au réseau privé, sans publication directe de son API sur Internet
  • Services d'automatisation contrôlés au niveau de leur santé, sans encore déclarer de consommation par un agent
🧭 Architecture — poste client, calcul séparé
séparation entre poste de dev et service d'inférence
VM302 (Windows 11, sans GPU local)
├── VSCodium · Git · PowerShell 7
├── Python 3.13 · Node.js 24 LTS
└── DeepSeek Harness (interface locale)
    └── service d'inférence séparé (réseau privé)
        └── accélération GPU distante

Le poste reste léger et sans GPU : le calcul est délégué à un service d'inférence hébergé séparément, joignable uniquement sur le réseau privé. Cette séparation isole l'outillage de développement du service de modèle.

🎯 Compétences illustrées
  • Préparation et validation d'un poste Windows virtualisé
  • Conception d'une chaîne de développement polyglotte
  • Installation maîtrisée d'un outil agentique fondé sur une architecture de plugins Cordis
  • Intégration d'un poste sans GPU à un service d'inférence séparé
  • Sélection de composants libres et séparation des dépendances propriétaires
  • Tests reproductibles et validation hors ligne
  • Séparation entre poste client, service d'inférence et automatisation
🚧 Limites & statut :
  • les chaînes Rust et C/C++ restent des travaux futurs ;
  • la comparaison des assistants et l'exécution d'un workflow d'automatisation par un agent restent à réaliser ;
  • DeepSeek Harness est encore diffusé en version préliminaire : il n'est pas présenté comme un composant stabilisé ;
  • la licence Windows et les composants matériels propriétaires interdisent de présenter l'ensemble comme « 100 % open source ».
