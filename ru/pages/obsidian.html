Obsidian

Личная база знаний — живая документация инфраструктуры On-Premise ИИ

Markdown Ведение заметок Knowledge base Граф связей Local-first
Документация · Средний уровень · 2024-2026
Почему Obsidian? При построении ИИ-инфраструктуры с нуля — Proxmox, GPU passthrough, локальные LLM, RAG, Python-конвейеры — памяти уже недостаточно. Мне нужен был инструмент, который хранит заметки локально, в чистом Markdown, без облачной подписки, и связывает понятия между собой. Obsidian стал спутником в строительстве всей этой инфраструктуры: каждая протестированная команда, каждая встреченная ошибка, каждое архитектурное решение фиксировались в отдельном vault. Этот портфолио отчасти является публичным синтезом этих записей.
Обзор

Obsidian — это локальный по умолчанию (local-first) редактор заметок в Markdown: файлы остаются на диске, в виде простого текста. Учётная запись не требуется, данные по умолчанию никуда в облако не отправляются. Его сила — в графе двунаправленных связей ([[wikilink]]), который превращает разрозненные заметки в навигируемую сеть знаний.

  • Файлы Markdown хранятся локально (C:\Notes\infra-vault)
  • Интерактивный граф связей между понятиями
  • Мгновенный полнотекстовый поиск по всему vault
  • Шаблоны для стандартизации ведения заметок
  • Плагины сообщества (Dataview, Kanban, Calendar…)
  • Опциональная синхронизация через OneDrive или Git

Конкретная роль в построении инфраструктуры

Vault infra-vault сопровождал каждый этап проекта — от технологического мониторинга до написания этого портфолио. Вот применения, которые реально имели значение:

📋 Журнал строительства

Одна заметка на рабочую сессию: цель, протестированные команды, встреченные ошибки, найденное решение. Незаменимо для возобновления работы после нескольких дней перерыва без потери контекста.

markdown — иллюстративный пример заметки сессии (не описывает текущую платформу)
## 2024-11-14 — GPU Passthrough VFIO
**Objectif :** Isoler la RTX 3090 pour la VM LLM

### Commandes testées
```bash
lspci -nn | grep NVIDIA
# 0000:01:00.0 [10de:2204]
```
### Problème rencontré
IOMMU group partagé → ajouter pcie_acs_override=downstream

### Solution
Kernel param : `intel_iommu=on iommu=pt pcie_acs_override=downstream,multifunction`

→ [[gpu_passthrough]] pour la doc finale

🗺️ Ментальная карта архитектуры

У каждого компонента инфраструктуры есть своя выделенная заметка, связанная через wikilink. Граф Obsidian визуализирует зависимости в реальном времени: Proxmox → ВМ LLM → Docker → Ollama → Open WebUI.

📚 База технологического мониторинга

Статьи, бенчмарки моделей, сравнения (LLaMA vs Mistral vs Phi), заметки по чтению о RAG и Qdrant. Всё централизовано, находится за 3 секунды благодаря полнотекстовому поиску.

Графовое представление vault

Графовое представление Obsidian визуально связывает заметки: каждая точка — заметка, каждая линия — связь. Оно выявляет тематические кластеры (инфраструктура, ИИ, DevOps…) и центральные заметки vault.

Средний
Пример — запрос Dataview

Dataview позволяет запрашивать vault как базу данных. Пример: вывести все текущие задачи по инфраструктуре, отсортированные по дате последнего изменения.

dataview — дашборд открытых задач
```dataview
TABLE
  file.mtime AS "Dernière modif",
  status AS "Statut",
  tags AS "Tags"
FROM "02-infrastructure" OR "03-ia"
WHERE status = "en-cours"
SORT file.mtime DESC
```
Результат: таблица автоматически обновляется при каждом открытии vault — без ручного ввода. Тот же принцип, что и представление проекта в инструменте вроде Notion, но полностью локально и в чистом Markdown.
От vault Obsidian к этому портфолио

Этот портфолио не был написан с нуля. Каждая HTML-страница — это публикуемая версия существующей заметки Obsidian, доработанная и оформленная. Рабочий процесс прост:

📝
1. Заметка сессии
Черновые заметки во время работы
↓
🗂️
2. Техническая карточка
Консолидация в 02-infrastructure/ или 03-ia/
↓
📄
3. Черновик портфолио
Написание в 06-portfolio/
↓
🌐
4. Опубликованная HTML-страница
portfolio.stephanemuraro.fr

Ключевое преимущество: заметка Obsidian остаётся источником истины. Если конфигурация меняется (версия Proxmox, обновлённая модель LLM), сначала обновляется заметка, затем синхронизируется HTML-страница.

Этот процесс также позволяет хранить в vault неопубликованную информацию (ключи API, внутренние IP-адреса, чувствительные отладочные заметки) без риска раскрыть её на GitHub.

Сам vault версионируется в приватном репозитории GitHub, отдельном от публичного репозитория портфолио.
