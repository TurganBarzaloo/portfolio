VM302 — Станция ИИ-разработки

Windows 11 · VSCodium · Python 3.13 · Node.js 24 LTS · DeepSeek Harness · удалённый вывод на GPU

Уровень: продвинутый
VM302 — это рабочая станция разработки на Windows 11, предназначенная для многоязычной разработки и оценки ассистентов программирования. У машины нет локального GPU: она использует отдельно размещённые мощности вывода, что отделяет клиентскую станцию от вычислительного сервиса.
✅ Проверенная база и цепочки инструментов
  • Виртуализированная база Windows 11, без локального GPU-ускорителя
  • VSCodium, Git и PowerShell 7 проверены функциональными тестами
  • Гостевая идентификация, сеть, гостевой агент и периферия повторно проверены
  • Python 3.13 — управление пакетами, виртуальное окружение, офлайн-тест стандартных библиотек
  • Node.js 24 LTS и npm — запуск локального теста JavaScript
  • DeepSeek Harness в зафиксированной предварительной версии: lockfile, целостность пакета, аудит зависимостей, скрипты установки и нативные модули проверены
  • Интерфейс Harness ограничен локальной машиной, первый профиль — только для чтения
🔎 Удалённый вывод и сохранность
  • Первый проверенный удалённый вывод с qwen3.6:35b: контрольный запрос вернул точно DSH_VM302_QWEN36_OK, без вызова инструментов
  • После перезагрузки станции: версии, конфигурация и история сессии сохранены
  • Новая сессия подтвердила ожидаемый ответ и удалённое ускорение на GPU
  • Доступ к сервису вывода ограничен частной сетью, без прямой публикации его API в интернете
  • Сервисы автоматизации проверены на уровне работоспособности, без объявления потребления агентом
🧭 Архитектура — клиентская станция, отдельные вычисления
разделение между станцией разработки и сервисом вывода
VM302 (Windows 11, без локального GPU)
├── VSCodium · Git · PowerShell 7
├── Python 3.13 · Node.js 24 LTS
└── DeepSeek Harness (локальный интерфейс)
    └── отдельный сервис вывода (частная сеть)
        └── удалённое ускорение на GPU

Станция остаётся лёгкой и без GPU: вычисления делегируются отдельно размещённому сервису вывода, доступному только в частной сети. Такое разделение изолирует инструменты разработки от сервиса модели.

🎯 Продемонстрированные навыки
  • Подготовка и проверка виртуализированной станции Windows
  • Проектирование многоязычной цепочки разработки
  • Контролируемая установка агентного инструмента на архитектуре плагинов Cordis
  • Интеграция станции без GPU с отдельным сервисом вывода
  • Выбор свободных компонентов и разделение проприетарных зависимостей
  • Воспроизводимые тесты и офлайн-проверка
  • Разделение клиентской станции, сервиса вывода и автоматизации
🚧 Ограничения и статус:
  • цепочки Rust и C/C++ остаются будущей работой;
  • сравнение ассистентов и выполнение сценария автоматизации агентом ещё предстоит сделать;
  • DeepSeek Harness всё ещё распространяется как предварительная версия: он не представлен как стабильный компонент;
  • лицензия Windows и проприетарные аппаратные компоненты не позволяют представлять всё как «100 % открытый код».
